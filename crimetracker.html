CrimeTracker

A crime reporting system that spans two platforms: reports are filed from a native Android app, with photo, video and audio evidence attached, and reviewed through a PHP and MySQL web backend.

Overview

The problem

Reporting an incident happens on a phone, in the moment. Reviewing reports happens later, at a desk, across many entries. One interface can't serve both well.

My approach

Two front ends over one data layer: a native Android app for filing with evidence attached, and a PHP web interface for browsing and reviewing what comes in.

Result

A working dual-platform system handling photo, video and audio evidence, with crime listings redesigned to be readable at a glance.

What it does

  • File a report from the phone — native Android app built in Kotlin
  • Evidence handling — photo, video and audio captured and attached to a report
  • Web backend — PHP and MySQL for storing, listing and browsing submitted reports
  • Firebase services — integrated alongside the PHP backend
  • Redesigned crime listings — the review interface reworked so entries scan quickly instead of reading like a raw table dump

Build notes

  • Two platforms, one source of truth

    Keeping the Android client and the web backend in agreement about the shape of a report, including its media attachments, was the core design work.

  • Media is heavier than text

    Photo, video and audio evidence changes how uploads, storage and listing views have to behave compared to a simple text form.

  • Android build and configuration issues

    A real share of the project went on diagnosing build and configuration failures rather than writing features — useful practice in reading errors properly instead of guessing.
